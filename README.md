# ELC — сайт и backend лицензирования

Проект включает:
- `client/` — сайт на React + TypeScript + Vite;
- `server/` — Node.js + Express + TypeScript + SQLite;
- `ELC-LICENSE-API.md` — контракт API для macOS-приложения на Swift/CryptoKit.

## Требования

- Node.js 22.x (рекомендуемая версия проекта);
- npm.

## Установка зависимостей

Из корня проекта:

```bash
npm run install:all
```

## Переменные окружения backend

Создайте `server/.env` локально. Не добавляйте его в Git и не передавайте третьим лицам.

Минимально необходимы:
- `PAYMENT_WEBHOOK_SECRET` — секрет проверки подписи вебхука;
- `ADMIN_TOKEN` — длинный случайный токен для внутреннего endpoint сброса привязки.

Не используйте опубликованные или демонстрационные значения в production. Остальные параметры имеют значения по умолчанию в `server/src/config.ts`; при необходимости задайте `PORT`, `CLIENT_URL`, `SERVER_URL`, `DB_PATH`, `PRICE_MINOR`, `CURRENCY`, `PAYMENT_PROVIDER` и параметры SMTP.

Для локальной разработки база по умолчанию создаётся в `server/data/elc.db` при запуске сервера. Каталог `server/data/` не входит в этот архив, чтобы не перезаписать пользовательские данные.

## Запуск разработки

В первом терминале из корня:

```bash
npm run dev:server
```

Во втором терминале:

```bash
npm run dev:client
```

## Сборка

Из корня:

```bash
npm run build
```

Production запуск backend:

```bash
npm start
```

## Покупка и выдача кода

Текущий провайдер `mock` — только тестовая имитация оплаты. Это не реальное списание денег. Код выдаётся после серверного подтверждения статуса покупки. SMTP настраивается отдельно; если SMTP не задан, код остаётся доступен на странице успешной покупки, а отправка письма не гарантируется.

Цена по умолчанию задаётся `PRICE_MINOR=40000`, то есть 400 RUB.

## Лицензирование macOS-приложения

Backend реализует:
1. `POST /api/activation/challenge` — выдача одноразового challenge;
2. `POST /api/activate` — первая или повторная активация с подписью ECDSA P-256;
3. `POST /api/activation/check` — проверка существующей привязки при запуске приложения.

Приватный ключ должен создаваться на Mac и храниться в Keychain. На сервер передаётся только публичный ключ в Base64 DER/SPKI. Подробный формат запросов и ответов находится в `ELC-LICENSE-API.md`.

Один код привязывается к одному публичному ключу. Повторная активация с тем же ключом разрешена; другой ключ получает отказ. Старые коды, привязанные через прежний `deviceId`, не переносятся автоматически: поддержка должна выполнить ручной сброс.

`POST /api/admin/reset` — внутренний endpoint поддержки. Он требует `x-admin-token`. Не встраивайте этот токен в сайт или macOS-приложение и не передавайте его разработчику клиентской части.

## Перед production deployment

1. Сделайте резервную копию SQLite.
2. Проверьте миграцию на копии базы.
3. Проверьте первую активацию, повторную активацию на том же Mac, отказ на другом Mac, проверку лицензии и ручной сброс.
4. Убедитесь, что Railway использует persistent volume и правильный `DB_PATH`.
5. Не выкладывайте backend до завершения интеграционных тестов со Swift-приложением.

## Секреты и локальные файлы

Архив не содержит `.env`, резервных копий `.env`, базы SQLite, `node_modules`, `.git` и собранных `dist`. Это намеренно: эти файлы локальны и/или могут содержать секреты и пользовательские данные.
